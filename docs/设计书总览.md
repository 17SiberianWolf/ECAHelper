## 0. TL;DR

一个**本地 Web 应用**（Python + SQLite，双击启动，浏览器打开），把你每月收到的 Excel 工时表导入并持久化，支持**按项目号 / 人员 / 时间段 / 组织 / 成本中心**多维检索统计，结果三层展示（总计→按月→按人）并支持 WBS 下钻、Top N 排行、趋势图、数据质量面板，导出中英双语 Excel/CSV。

**数据现状基线**：44 个源文件全量解析（均为有效工时表，2023.02–2026.09 无缺月），**33,015 条明细行**，累积 **1,572,771.8 h**。源数据存在 4 类会算错数的陷阱，已在数据模型层全部处理（详见附录 A）。

## 3. 技术栈（已实现）

Python 3.13 + **Flask**（Jinja2 服务端渲染）+ **Waitress**（本机常驻）+ **SQLite** + openpyxl（解析/导出）+ **原生 SVG 图表**（`web/static/js/charts.js`，离线、无任何 CDN / 第三方图表库）+ 原生 CSS/JS。
**不引入 Node/React 构建链、不依赖 pandas、不引入任何 CDN**（离线优先）。启动方式：`start.bat` 一键建 venv、装依赖、起服务、自动开浏览器。

## 4. 决策状态（开放问题已全部确认）

12 项核心决策之外发现的 11 个开放问题，已于 2026-09-21 由用户全部拍板，以下取值为最终实现依据：

| 编号 | 问题 | 最终决定 |
|------|------|----------|
| Q1 | 空 Resource ID 行归属 | 落库置 `__UNKNOWN__`，归「未标识人员」桶，不强制合并 ✅ |
| Q2 | 同一人多 ID 是否自动合并 | **默认不自动合并**；质量面板「疑似同 ID 候选」须保守——`WATA` 与 `WATA02` 是本质不同的两个人，不得作为合并建议 ✅ |
| Q3 | 标记行如何「用户决定是否处理」 | 质量面板勾选「从统计排除」，`exclusion` 持久化，默认不排除 ✅ |
| Q4 | 同名月份文件重导 | 默认跳过（不静默翻倍），可选覆盖/副本 ✅ |
| Q5 | 「单季」指哪个季 | 默认当前自然季，可下拉选年月 ✅ |
| Q6 | 组织 v1/v2 口径不一致 | 仅 UI 提示，不强行归一 ✅ |
| Q7 | 导出双语是否含业务枚举中文映射 | 表头双语必做，Task 等业务值做可选中文映射 ✅ |
| Q8 | 0 工时行是否计入 | 计入行数、合计为 0 ✅ |
| +1 | 图表库 | **原生 SVG 离线渲染**（无 ECharts / 无 CDN，纯离线） ✅ |
| +2 | 启动端口 | 固定 5000，冲突 +1 回退 ✅ |
| +3 | 导出文件命名 | `导出_<类型>_<YYYYMMDD_HHMM>.<xlsx|csv>` ✅ |

> 实现阶段以本表 + 第 1 节 12 项核心决策为准。图表实现因离线沙箱无法下载 ECharts，已按决策 +1 改用**原生 SVG 离线渲染**（实现见 `web/static/js/charts.js`，无任何 CDN / 第三方库），详见 `docs/增量设计书-第二轮迭代.md`。

## 6. 风险与备注

- 文件名是唯一可靠时间源（表内 From/To 与游离日期列均已证不可信）——已强制只认文件名。
- 组织字段 v1/v2 口径差异大（v1 多 `SCF/EAR/EAL`，v2 多 `SX**` 驻点码），按 Q6 仅提示不归一。
- 应用不强制合并任何 ID/姓名，所有清洗均可回溯到原始行（`source_file + source_row`）。
- 日志与审计仅落本机（`data/logs/` 与 `audit_log`），无任何远程上报 / 同步（决策 6 / AC-07-5）。
