# ECAHelper 产品需求文档（PRD）

> 版本：v1.0 ｜ 作者：产品经理 许清楚 ｜ 关联：附录A《源数据实测报告》（45 文件全量解析）
> 形态：本地 Web 应用（Python + SQLite，双击启动，浏览器打开）｜ 语言：中文界面，导出报表中英双语
> 范围：仅本机单人使用，无登录/权限体系

---

## 1. 产品概述

**一句话定位**：一个把公司每月下发的 Excel 工时表导入、持久化、并能按「项目 / 人员 / 时间段 / 组织 / 成本中心」快速多维检索统计与导出的本地分析工具。

**解决的问题**：
- 项目经理月底收到工时表后，要翻遍所有月份 Excel、手工累加某项目/某员工的工时——费力且易错。
- 源数据存在大量"脏活"：表位置不固定、两代字段结构、人名/工号/项目号写法混乱、20% 行无项目号、重复行与日期型脏数据。

**不解决的问题（边界）**：
- 不做计时器、审批流、GPS、移动端、发票计费、薪酬对接、权限/登录体系（同类工具调研已排除）。
- 不做工时占比、人均利用率分析（用户明确不要）。
- 不做每日明细（数据最细粒度就是"月"）。
- 本期不引入项目主数据（`在管项目2026.08.xlsx`），不做 Project ID 补全。

**必须遵守的 12 项已锁定决策**（贯穿全文，不可改动）：Resource ID 主键 / 无项目号行项目维度排除·人员维度保留为"非项目工时" / 重复与异常行标记不删 / 暂不引主数据 / 年-月区间+快捷按钮 / 项目号归一化精确匹配+WBS 下钻 / 三层结果展示 / Top N+趋势+组织成本中心+质量面板 / 不做占比利用率 / 本地 Web(Python+SQLite) / 本机单人 / 中文界面+中英双语导出。

## 2. 用户画像与核心场景

**用户画像**：冶金连铸自动化工程公司的**项目经理**，向德国老板汇报、与欧洲同事协作；每月处理 1 份公司下发的当月员工工时表 Excel；需要跨多月、跨人员/项目做工时统计与汇报。

### 核心 User Story

**US-1 按项目查累计工时**（对应痛点 1）
> As a 项目经理, I want 输入一个 Project ID 并选择时间区间，系统自动跨所有已导入月份累加该项目工时, so that 我不必再逐月翻表手工求和。

**US-2 按员工查项目分布**（对应痛点 2）
> As a 项目经理, I want 输入某员工（或其一任姓名写法）并选时间段，看到他各项目号填了多少小时、以及非项目工时（休假/采购等）各多少, so that 我能快速回答"这个人这段时间在忙什么"。

**US-3 临时多维统计**（对应痛点 3）
> As a 项目经理, I want 在时间段基础上叠加组织/成本中心/任务等过滤条件做即席检索, so that 老板临时要的各类口径我都能自助产出。

### 补充 User Story（产品必要场景）

**US-4 一键导入全量历史**
> As a 项目经理, I want 把整个 OriginSource 目录拖入导入页即批量导入全部月份, so that 首次搭建不用一个月个月点。

**US-5 导出可直接转发海外的报表**
> As a 项目经理, I want 把任一查询结果导出 Excel/CSV 且表头中英双语, so that 我能直接发给德国老板和欧洲同事而不用再翻译列名。

**US-6 看见数据哪里不干净**
> As a 项目经理, I want 在"数据质量面板"看到空项目号、重复行、日期型脏数据等指标及明细, so that 我在汇报前能判断统计口径是否可信。

## 3. 需求池

优先级：P0 必须有｜P1 应该有｜P2 锦上添花。每条含「需求描述 + 验收标准（可验证判定条件）」。

### P0（必须有，共 12 条）

**P0-1 批量文件导入（自动定位数据表）**
- 描述：导入页支持选择目录或批量选中 `.xlsx` 导入；自动跳过 `~$` 临时锁文件与 `在管项目2026.08.xlsx` 等主数据文件（本期不引入）；**忽略每张文件的前两张 Sheet（透视表）**，靠"同时含 `Resourcename` 与 `Actuals Total in h`"定位数据 Sheet 与表头行（第 1/2/3 行均可能）。
- 验收标准：
  - 导入 44 个有效工时表后，明细行数 = **33,015**（含空 Project ID 与异常行，均保留）。
  - `2024.12`（仅 1 张 Sheet）、`2024.10`（2 张）、`2023.2`（表头第 1 行）均能被正确定位。
  - `~$...` 与 `在管项目2026.08.xlsx` 被跳过且不报错；无法定位数据表的文件被列出并提示。

**P0-2 文件名月份解析（权威时间依据）**
- 描述：仅以**文件名**解析报告月份 `YYYY-MM`（如 `Timesheet of 2023.6 including SC.xlsx`→2023-06；`2025.01including SC.xlsx` 缺空格也要解析成功）。忽略文件内 "From...to..." 与游离日期列。
- 验收标准：44 个文件名全部解析出唯一 `YYYY-MM`；解析结果与已知序列（2023.02–2026.09 无缺月）一致；解析失败的文件名被列出并跳过导入。

**P0-3 数据持久化（SQLite，行级落库 + 审计标记）**
- 描述：导入后行级明细落库 SQLite；每条含派生字段 `report_month`（派生）、`source_file`、`source_sheet`、`source_row` 及质量标记 `is_duplicate`、`is_anomaly_actuals`、`import_batch_id`。重复导入同名文件需可识别（提示覆盖/跳过/副本）。
- 验收标准：库中保留全部 33,015 行（含空 Project ID、异常行，不删）；任意行可回溯到 `source_file + source_row`；同名文件重复导入时**不静默翻倍**（默认跳过并提示）。

**P0-4 人员标识与归一化（Resource ID 主键）**
- 描述：以 Resource ID **归一化值**（去空格、统一大写）为主键；同一 ID 的多种姓名写法归入该 ID 的别名列表，统一显示一个规范名（参考：`waxi`/`WAXI`、`Caoz`/`CAOZ` 归并；`Li, Bo`/`Li Bo`/`Li，Bo` 视为同 ID 的别名）。
- 验收标准：260 个 ID 各唯一；查询某 ID 能聚合其所有姓名变体对应的行；人员搜索支持按任一别名命中。

**P0-5 项目标识归一化与精确匹配**
- 描述：Project ID 归一化（去空格、统一大小写、统一转字符串）后**精确匹配**；支持用户输入原始形态（含尾空格/大小写/数字/浮点/WBS 形式）自动归一化查询。
- 验收标准：5 种形态 `O 1900.008` / `E20067-000 ` / `70463`(int) / `0.0001`(float) / `O 1341.176.01.01.0028` 均能归一化并被精确命中；查 `O 1900.008` 也能命中存储为 `O 1900.008 `（尾空格）的行。

**P0-6 按项目号 + 时间段查工时**
- 描述：输入项目号（归一化精确匹配）+ 年-月起止区间（含快捷：今年 / 去年 / 全部 / 单季），返回该项目工时聚合。
- 验收标准：返回三层结果（见 P0-9）；区间内无数据的项目显示 0 而非报错；WBS 下钻视图随附（见 P0-10）。

**P0-7 按员工 + 时间段查工时（含非项目工时）**
- 描述：输入人员（Resource ID 或其任一姓名别名）+ 时间段，返回该人工时。**项目维度**聚合排除空 Project ID 行；**人员维度**保留空 Project ID 行并归类为"非项目工时"单列（按 Task 细分）。
- 验收标准：结果含"项目工时合计"与"非项目工时合计（Leave / Procurement services / 其他）"两栏；某人总工时 = 项目工时 + 非项目工时；空 Project ID ≈ **6,589 行**（Leave 3,293 + Procurement services 2,523 + 空白 576 + SCF(年假)79 + SCF(病假)35 + 其他 83）。

**P0-8 按时间段多维检索（综合检索）**
- 描述：按时间段 + 可选过滤维度（Organization / Cost Center / Task / 是否含空项目号 / 人员 / 项目）即席检索与聚合。
- 验收标准：仅用时间段可返回全量聚合；可叠加 Organization、Cost Center 过滤且结果正确；返回三层结构。

**P0-9 结果三层展示**
- 描述：所有工时查询结果统一三层：① 顶部总计 → ② 按月分布（按 `YYYY-MM` 升序）→ ③ 按人明细（可折叠）。
- 验收标准：项目/员工/综合三类查询页均呈现该三层；按人明细可点击折叠/展开；三层合计数值一致（总计 = 各月之和 = 各人之和）。

**P0-10 WBS 下钻视图**
- 描述：项目/综合查询结果默认附带 **WBS Nr 下一级下钻视图**：将 WBS Nr 按 `.` 分段，展示其下一级的工时聚合，可逐层展开（例：项目 `O 1830.061` 的下一级 `O 1830.061.09`）。
- 验收标准：对含 WBS 的项目（如 `O 1830.061`→`O 1830.061.09`）能展示下一级聚合；下钻各层合计与项目总工时不矛盾（一致）。

**P0-11 导出（Excel / CSV，中英双语）**
- 描述：任意查询结果可导出 Excel 与 CSV；表头字段名中英双语（如 `Project ID / 项目号`、`Actuals Total in h / 实际工时(h)`），便于直接转发德国老板/欧洲同事。
- 验收标准：导出文件含双语表头；Excel 与 CSV 内容一致；导出范围与当前查询/筛选完全一致。

**P0-12 数据质量面板**
- 描述：全局展示质量指标：总行数、空 Project ID 行数及 Task 分类、重复行（按文件）、异常值（日期型 Actuals）、0 工时行、人员姓名变体数、空/异常 Resource ID；每次导入生成导入报告列出标记明细。
- 验收标准：面板数字与实际库一致（空 Project ID ≈ 6,589；重复行涉及 **33 文件**、共 137 行 / 100 重复组；异常 Actuals = **14 行**全在 2023.2；0 工时行 **93 行**；197/260 ID 存在姓名变体）；面板可下钻查看被标记的具体行。

### P1（应该有，共 4 条）

**P1-1 Top N 排行**：按工时对人员 / 项目 / 组织做 Top N 排行（N 可配，默认 10）。验收：排行榜数值与底层聚合一致；可切换维度与 N。

**P1-2 按月趋势图**：在查询区间内绘制月度工时折线/柱状趋势图。验收：`YYYY-MM` 升序、无数据的月份显示 0 点不断裂；图与实际合计一致。

**P1-3 Organization 维度统计**：按 Organization 聚合工时；UI 明示 v1/v2 口径差异与空值（2,254 行）、`SX**` 驻点编码（50+ 种）。验收：如实展示原始值，标注"跨版本口径可能不一致"提示，不强行归一。

**P1-4 Cost Center 维度统计**：按 Cost Center（数字代码）聚合工时。验收：代码作为字符串聚合、不丢前导零/不误算。

### P2（锦上添花，共 4 条）

**P2-1 人员 × 项目交叉矩阵**：行=人、列=项目、值=工时（可排序/导出）。验收：矩阵合计与三层展示的总计一致。

**P2-2 疑似同一人/同 ID 候选与别名管理 UI**：基于姓名变体、拆分 ID（如 `WATA`/`WATA02`、`LIXI`/`LIXN`）给出"疑似合并"候选清单 + 手动合并开关。验收：合并后生成映射并影响后续聚合；默认不自动合并。

**P2-3 查询快照 / 常用视图保存**：保存当前查询条件与筛选为一键复用视图。验收：可保存、列出、删除；恢复后结果一致。

**P2-4 空 Resource ID 行归类处理 UI**：P0 先原样落库并标记，P2 提供将空 ID 行归类到"未标识人员"或按姓名临时归并的操作界面。验收：操作可回溯、不破坏原始行。

## 4. 数据字段定义表（v1/v2 统一映射）

> 内部统一字段以 **resource_id_norm** 为主键键、**project_id_norm** 为项目匹配键、**report_month** 为权威时间键。v1（2023.02–2024.06，17 文件，9 列）与 v2（2024.07–2026.09，28 文件，16–17 列）按来源列映射如下。

| 内部字段 | 类型 | 必填 | 来源（v1 / v2） | 备注 |
|---|---|---|---|---|
| `resource_id_norm` | string(PK) | 是(归一化) | Resource ID | 去空格+大写；空值归入占位 `__UNKNOWN__`（见待确认 Q1） |
| `resource_id_raw` | string | 否 | Resource ID | 原始值，含大小写/空 |
| `person_name_canonical` | string | 否 | Resourcename | 规范显示名 |
| `person_name_aliases` | json/list | 否 | Resourcename | 同一 ID 全部写法（`Li, Bo`/`Li Bo`/`Li，Bo`…） |
| `organization` | string | 否 | Organization | 含空(2,254)、`SX**` 驻点码；v1/v2 口径可能不同 |
| `cost_center` | string | 否 | Cost Center | 数字代码，统一转字符串 |
| `wh_cost_center` | string | 否 | — / WH Cost Center | 仅 v2 |
| `project_id_norm` | string(匹配键) | 否 | Project ID | 归一化精确匹配；空=非项目工时 |
| `project_id_raw` | string | 否 | Project ID | 原始（5 种形态） |
| `project_name` | string | 否 | Project | |
| `task` | string | 否 | Task | 空项目号时用于分类（Leave 等） |
| `wbs_nr` | string | 否 | WBS Nr | 下钻用，按 `.` 分段 |
| `to_wbs_no` | string | 否 | — / To WBS No. | 仅 v2 |
| `to_cost_center` | string | 否 | — / To Cost Center | 仅 v2 |
| `to_internal_order` | string | 否 | — / To Internal Order | 仅 v2 |
| `to_reference_proj_no` | string | 否 | — / To Reference Proj.No. | 仅 v2 |
| `reference_proj_name` | string | 否 | — / Reference Proj.Name | 仅 v2 |
| `actuals_total_h` | float | 是(统计) | Actuals Total in h | 日期型→`is_anomaly_actuals`；0/空→计行数、合计 0 |
| `transaction_group` | string | 否 | — / Transaction Group | 仅 v2 |
| `site_type` | string | 否 | — / Site Type | 仅 v2（部分文件无） |
| `report_month` | string `YYYY-MM` | 是(派生) | **文件名** | 权威时间，忽略表内日期 |
| `source_file` | string | 是 | 文件名 | 审计溯源 |
| `source_sheet` | string | 是 | Sheet 名 | |
| `source_row` | int | 是 | 行号 | |
| `is_duplicate` | bool | 是 | 计算 | 同文件内完全重复（33 文件） |
| `is_anomaly_actuals` | bool | 是 | 计算 | 日期型工时（2023.2 共 14 行） |
| `import_batch_id` | string | 是 | 导入批次 | |

**归一化与匹配规则**：
1. Resource ID：`trim` + `upper` → 主键；空 → `__UNKNOWN__`。
2. Project ID：`trim` + `upper`（统一转 string 后处理）→ 匹配键；5 形态统一可比。
3. Actuals：`numeric` 解析；值为 `datetime`（Excel 日期）→ 标记异常；空/0 → 计行数、合计 0（无负工时，全量 0 条）。
4. WBS Nr：按 `.` 分段用于下钻。
5. report_month：文件名正则提取 `YYYY.M[M]`（兼容缺空格如 `2025.01including SC`）。

## 6. 待确认问题（需用户拍板）

> 以下问题在 12 项锁定决策之外发现，需用户确认；每项附**建议答案**。

**Q1 空 Resource ID 行如何归属？**
- 事实：空 Resource ID 行真实存在（如 `('', '', '', … 'O 1341.176…', …)`），且空 ID 关联到多个姓名，不兼容"Resource ID 主键"。
- 建议：P0 原样落库，`resource_id_norm` 置占位 `__UNKNOWN__`，统计归入"未标识人员"桶；不强制合并。是否接受？

**Q2 疑似同一人被拆成两个 ID（WATA/WATA02、LIXI/LIXN）是否自动合并？**
- 事实：12 决策只要求"姓名变体归并到同一 ID"，未覆盖"同一人多个 ID"（共 17 个姓名→多 ID）。
- 建议：默认**不自动合并**（防误并），在数据质量面板/人员页提供"疑似同 ID 候选"清单 + 手动合并开关，合并后生成映射表。是否同意？

**Q3 "标记不删、用户决定是否处理"如何落到产品？**
- 建议：数据质量面板对每个重复组/异常组提供"从统计中排除"勾选，状态持久化；**默认不排除**（即统计含全部原始行），与"保留原始行"一致。是否同意默认含全部、靠勾选排除？

**Q4 重新导入同名月份文件的行为？**
- 事实：月度文件每月新增，误重导会翻倍。
- 建议：导入时检测 `source_file` 已存在 → 提示"覆盖 / 跳过 / 新增副本"，**默认跳过**。是否同意默认跳过？

**Q5 "单季"快捷按钮指哪个季？**
- 建议：默认"当前自然季"（按系统日期），并提供下拉选具体年份+季度。是否同意？

**Q6 组织维度 v1/v2 口径不一致如何呈现？**
- 事实：附录警告 v1 多 `SCF/EAR/EAL`、v2 多 `SX**`，语义可能不同；空值 2,254。
- 建议：如实展示原始值，UI 明示"组织字段跨版本口径可能不一致"；不强行归一；`SX**` 与主流组织并列。是否同意仅做口径提示、不强行合并？

**Q7 导出"中英双语"是否含业务枚举值映射？**
- 事实：决策说"字段名双语"；但 Task 值（Leave / Procurement services）德国老板可读、中文老板或需中文。
- 建议：表头字段名双语；Task 等业务枚举提供一层**可选中文映射**（Leave=休假、Procurement services=采购服务），作为附注列或单独工作表。是否要做业务值映射？

**Q8 0 工时行（93 行，其中真正 0 工时 79 行、14 行异常占位）是否计入统计？**
- 事实：无负工时，但存在 93 行 0 值（含 14 行异常占位，真正 0 工时 79 行；多为空 Actuals）。
- 建议：保留并计入行数，工时为 0 不影响合计；在质量面板单独列出口径。是否同意计入行数、合计为 0？
