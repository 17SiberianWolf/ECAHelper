# ECAHelper 部署手册

> 适用版本：重构后可移植版（`src/` + `web/` + `data/` 三层布局）
> 适用对象：单机使用者 / 内部工具管理员（非开发人员亦可照做）
> 关联文档：`docs/重构设计书.md`（结构与路径设计）、`docs/用户使用手册.md`（功能操作）

---

## 1. 三种交付形态一览

| 形态 | 适用场景 | 需要的文件 | 入口 |
|------|----------|-----------|------|
| **A. 源码一键部署** | 目标机装了 Python，直接跑 | 整个项目目录 | `deploy.bat` |
| **B. 源码启动**（已部署过） | 日常启动 | 整个项目目录 | `start.bat` |
| **C. 打包为 exe** | 目标机**没有** Python | `dist\ECAHelper\` 整个文件夹 | `ECAHelper.exe` |

> 无论哪种形态，**运行数据（数据库 / 导出）与只读资源（模板 / 静态 / 源数据）都相对程序目录定位**，
> 因此整个目录可整体复制到任意路径（含 U 盘、其它盘符），无需修改任何配置。

---

## 2. 环境要求

- **操作系统**：Windows 10 / 11（64 位）。
- **形态 A / B**：需安装 **Python 3.10 或更高版本**（推荐 3.11–3.13）。
  - 下载：<https://www.python.org/downloads/>，安装时**务必勾选 “Add Python to PATH”**。
  - 依赖（flask / waitress / openpyxl 等）由脚本自动安装，无需手工处理。
- **形态 C**：目标机**无需** Python（已随包打包运行时）。
- **磁盘**：源码约数十 MB；含 `OriginSource` 源表与数据库后约数百 MB。
- **权限**：程序目录需**可写**（数据库与导出会写在程序目录下）。请勿放在 `C:\Program Files\` 等只读目录。

## 3. 形态 A：源码一键部署（推荐首次使用）

### 3.1 目录结构（部署前）

```
ECAHelper\
├─ src\                 # 后端（app.py / config.py / eca_helper\）
├─ web\                 # 前端（templates\ / static\）
├─ data\                # 运行数据（eca_helper.db 与 exports\，首次运行自动生成）
├─ OriginSource\        # 源 Excel 工时表（数据来源）
├─ tools\               # 开发期校验脚本（使用者可忽略）
├─ docs\                # 文档
├─ requirements.txt     # 运行依赖
├─ requirements-dev.txt # 打包依赖（仅形态 C 需要）
├─ deploy.bat           # 一键部署
├─ start.bat            # 启动
├─ setup_env.bat        # 仅建环境（不启动）
├─ build_exe.bat        # 打包 exe
└─ ECAHelper.spec       # PyInstaller 规格
```

### 3.2 部署步骤

1. 把整个 `ECAHelper` 文件夹复制到目标机任意可写路径（例如 `D:\ECAHelper`）。
2. 确认 `OriginSource\` 内已放入本期要统计的 `.xlsx` 工时表。
3. **双击 `deploy.bat`**。脚本会：
   - 检测系统 Python（版本需 ≥ 3.10，不满足会给出中文提示并退出）；
   - 在项目内创建虚拟环境 `.venv\`；
   - 升级 `pip` 并按 `requirements.txt` 安装依赖；
   - 自动调用 `start.bat` 启动服务。
4. 启动成功后会打印访问地址（默认 `http://127.0.0.1:5000`，被占用则自动 +1），并**自动打开浏览器**。
5. 首次运行若数据库为空，会**自动导入** `OriginSource\` 下的全部工时表（同步执行，控制台会显示进度），
   导入完成后浏览器刷新即可看到数据。

> **停止服务**：关闭该命令行窗口，或在窗口内按 `Ctrl+C`。

## 4. 形态 B：日常启动

- 已通过 `deploy.bat` 部署过（存在 `.venv\`）→ **双击 `start.bat`** 即可。
- 若未部署过 `.venv`，`start.bat` 会依序尝试：
  1. 项目内 `.venv\Scripts\python.exe`；
  2. 系统 `python`（PATH 中，需已安装依赖）；
  3. `py -3` 启动器（需已安装依赖）。
- 三者都不可用时，会给出**明确中文提示**并等待按键（请先运行 `deploy.bat`）。
- 运行日志写入项目根目录 `startup.log`，排错时先看它。

> 只想准备好环境、暂不启动：双击 `setup_env.bat`（仅建 `.venv` 并装依赖）。

---

## 5. 形态 C：打包为独立 exe（目标机无 Python）

### 5.1 打包机准备（需 Python ≥ 3.10）

1. 先执行**形态 A 的部署**（保证存在 `.venv\`，其中含运行依赖）。
2. **双击 `build_exe.bat`**。脚本会：
   - 确保 `.venv` 中已安装 `pyinstaller`（缺失则按 `requirements-dev.txt` 安装）；
   - 以 `ECAHelper.spec`（onedir 模式）执行 `<.venv>\python -m PyInstaller --noconfirm --clean ECAHelper.spec`；
   - 把 `OriginSource\` 复制到 `dist\ECAHelper\` 下；
   - 在 `dist\ECAHelper\` 下创建空的 `data\exports\`。
3. 打包完成后，产物位于 **`dist\ECAHelper\`**（整个文件夹即独立运行包，含 `ECAHelper.exe` 与 `_internal\`）。

### 5.2 目标机运行

1. 把 **`dist\ECAHelper\` 整个文件夹**复制到目标机任意可写路径（如 `D:\ECAHelper`）。
2. **双击 `ECAHelper.exe`**：
   - 首次运行若同级 `data\eca_helper.db` 不存在，会自动从同级 `OriginSource\` 导入全部工时表；
   - 数据库 `data\eca_helper.db` 与导出 `data\exports\` 均生成在 **exe 同级目录**（不会写入临时解包目录，退出不丢）。
3. 浏览器自动打开首页；如需手动访问，见窗口打印的地址。

> **注意**：exe 为**控制台程序**，运行时请勿关闭其命令行窗口（关闭即停止服务）。
> 若把 exe 放在只读目录（如 `C:\Program Files\`），程序会打印一行提示并将数据改存到
> `%LOCALAPPDATA%\ECAHelper`（数据库与导出都在那里），程序仍可正常使用。

## 6. 数据迁移（换机 / 备份 / 还原）

数据与源表均在程序目录内，**手动复制即可**：

| 要迁移的内容 | 复制来源 | 复制目标（新机程序目录下） |
|--------------|----------|----------------------------|
| 已导入的数据库 | `data\eca_helper.db` | `data\eca_helper.db` |
| 已导出的文件 | `data\exports\*` | `data\exports\` |
| 源工时表 | `OriginSource\*` | `OriginSource\` |

- 只关心**查询结果**：至少要带 `data\eca_helper.db`。
- 想在新机**重新导入**：只带 `OriginSource\`，删除（或不带）`data\eca_helper.db`，首次启动会自动导入。
- exe 形态同样适用：把上述内容复制到 `dist\ECAHelper\` 对应的 `data\` 与 `OriginSource\` 下即可。

> 幂等：导入按「文件名」判重，重复导入同名文件**不会翻倍**；重新启动不会重复导入。

## 7. 常见问题（FAQ）

**Q1. 双击 `start.bat` / `deploy.bat` 一闪而过？**
窗口末尾有 `pause`，正常不会闪退。若真闪退，多为中文乱码或环境异常，请查看项目根目录 `startup.log`。
另：`.bat` 文件以 GBK 编码保存，请用记事本“另存为”时保持 ANSI/GBK，勿转成 UTF-8。

**Q2. 提示「未找到可用的 Python 运行环境」？**
未安装 Python 或未加入 PATH。请安装 Python ≥ 3.10 并勾选 “Add Python to PATH”，或直接使用 exe 形态（形态 C）。

**Q3. `deploy.bat` 卡在 `pip install` 或报网络错误？**
依赖安装需要联网。若内网受限，可换用已装好依赖的条件，或使用 exe 形态交付。

**Q4. 浏览器没自动打开 / 想换端口？**
浏览器未弹出时，手动访问控制台打印的地址。默认端口 `5000`，被占用会自动 +1（看打印地址）。

**Q5. 首页有页面但没数据？**
说明数据库为空且 `OriginSource\` 缺失或为空。请确认 `OriginSource\` 内有 `.xlsx` 工时表，重启后会自动导入；
也可在“导入”页手动触发导入。

**Q6. 端口 5000 被占用会怎样？**
程序自动顺延到 5001、5002……并以实际端口启动；控制台与 `startup.log` 会打印实际地址。

**Q7. 导入很慢正常吗？**
首次全量导入数十个 Excel（约数万行）需数十秒，属正常。导入期间控制台会提示“正在自动导入……请稍候”。

**Q8. 数据库会被写进 exe 内部吗？**
不会。数据库与导出一律写在 **exe 同级目录**（或只读时的 `%LOCALAPPDATA%\ECAHelper`），**绝不**写入临时解包目录。

**Q9. 想整体搬到别的盘 / U 盘？**
直接把整个程序目录复制过去即可；布局是相对路径，无需改配置。注意目标路径需**可写且不含特殊字符**。

**Q10. `.venv` 复制到新机后启动失败？**
虚拟环境与本机 Python 路径绑定，跨机复制会失效。请在**新机上重新运行 `deploy.bat`**（若旧 `.venv` 残留，
`start.bat` 校验失败后会自动回退到系统 Python；也可先删除 `.venv\` 再部署）。

## 8. 关键目录与文件说明

| 路径 | 说明 | 可否删除 |
|------|------|----------|
| `src\` | 后端源码（入口 `src\app.py`） | 否 |
| `web\` | 模板与静态资源 | 否 |
| `data\eca_helper.db` | 运行数据库 | 可（重启会重建/重导） |
| `data\exports\` | 导出的 Excel/CSV | 可（清理旧导出） |
| `OriginSource\` | 源 Excel 工时表 | 否（数据来源） |
| `.venv\` | 项目内虚拟环境 | 可（重新 `deploy.bat` 会重建） |
| `startup.log` | 运行日志 | 可 |
| `dist\` `build\` | 打包产物 | 可（形态 C 的成品在 `dist\ECAHelper\`） |
